# 阶段7：浏览器经营分析看板

> 阶段原始档案：保留当时的任务、决定和验证记录。当前使用方法见[使用指南](../../USER_GUIDE.md)，持续更新见[项目日志](../../PROJECT_LOG.md)。文中的阶段输出路径属于历史记录。


后续进度：阶段8已在同一预算比较页加入收入、毛利与公司利润差异桥，详见21指南。本文仍用于学习看板基础操作与数据口径。

本阶段把阶段5的标准数据、阶段6的统一财务计算放进浏览器。你可以选择月份和业务范围、查看图表、比较预算、下载结果。默认完整模拟文件已经准备好，先打开页面操作，再阅读代码。

页面交互、展示与下载、真实临时MySQL读取验证已经通过。当前项目使用Streamlit 1.65和Plotly 7.1，依赖在项目的`.venv`中；本机可以直接运行，不需要再安装Navicat或另一个数据库程序。

## 1. 启动与停止

在PowerShell执行，先进入项目目录：

```powershell
# 将下一行替换成自己电脑的项目目录
Set-Location -LiteralPath '<项目目录绝对路径>'
powershell -NoProfile -ExecutionPolicy Bypass -File '.\scripts\run_stage7.ps1'
```

默认打开“经营分析工作台”，地址为：

```text
http://127.0.0.1:8501
```

如果浏览器没有自动打开，复制地址到浏览器。默认来源是“完整模拟数据”，从本地文件读取，不需要MySQL密码。第一次读取会显示“正在核对数据并准备看板”，完成后出现指标与图表。

保持PowerShell窗口运行。关闭浏览器不会停止程序；回到该PowerShell窗口按`Ctrl+C`才会停止看板。下次使用时重新执行启动命令。

如果8501端口已经被其他程序占用，可以改成8502：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File '.\scripts\run_stage7.ps1' -Port 8502
```

这时在浏览器打开`http://127.0.0.1:8502`。当前是本机程序，网址中的127.0.0.1表示这台电脑。

## 2. 先理解统一筛选

左侧选择“数据来源”和“页面”；页面上方选择分析月份、预算版本、显示单位以及商品、渠道、区域。窗口较窄时，可以先展开左侧菜单。

| 控件 | 用法 |
|---|---|
| 分析月份 | 选择要观察的自然月，默认选最后一个完整实际月 |
| 商品、渠道、区域 | 留空表示该维度全部；同一维度选多个编码表示任一编码 |
| 预算版本 | 只使用选中的一个版本，不把不同版本相加 |
| 元、万元 | 改变卡片和图表的显示尺度；明细表及CSV金额仍为精确元 |
| 刷新文件数据 | 重新读取、校验来源文件，更新当前数据快照 |

不同维度之间采用交集。例如商品P001、渠道C02、区域R02，表示“P001且C02且R02”。把商品选为P001和P002，表示“P001或P002”，同时仍须满足选中的渠道与区域。

页面上的“当前范围”说明用于核对筛选。公司费用和经营利润采用公司全部业务口径，不随商品、渠道、区域筛选变化；共同费用尚未分摊到商品。

## 3. 五个页面分别做什么

| 页面 | 先完成的操作 | 应当理解的结果 |
|---|---|---|
| 经营总览 | 查看2026年9月，再选择一个商品 | 当前范围的收入、成本、毛利与毛利率会变化；公司费用和经营利润仍是全公司数 |
| 月度趋势 | 设置趋势起始月份，切换当前月份 | 按连续自然月观察收入和毛利；环比对上一个月，同比对上年同月，图中空缺代表未知 |
| 维度分析 | 依次选商品、渠道、区域，并按收入或毛利排序 | 找出贡献较大的业务范围；维度展示毛利，不直接分摊公司利润 |
| 预算比较 | 查看销售预算，再看公司费用和经营利润预算 | 差额为实际减预算；费用超预算显示不利；明细可定位缺预算的实际维度 |
| 数据与下载 | 切换销售、退款、公司费用、字段映射与校验标签 | 从原始标准明细核对汇总数字，并下载与当前范围一致的文件 |

在“经营总览”还可以查看本年累计与下载当前指标JSON包。累计必须完整覆盖本年1月至所选月，不能仅把现有几个月相加当作正常年度累计。

在“维度分析”，同一订单含多个商品时，各商品组的订单数可能涉及同一个订单。因此不能把商品组订单数简单相加，作为公司订单数。

左侧把数据来源改成“小样本核对”，月份选2026年9月，三个维度均留空，单位选元。预期为：

| 指标 | 金额，元 |
|---|---:|
| 净收入 | 3240 |
| 净成本 | 2055 |
| 毛利 | 1185 |
| 公司费用 | 400 |
| 公司经营利润 | 785 |

再选商品P001、渠道C02、区域R02：当前范围净收入550、净成本350、毛利200元。公司费用仍为400元，公司经营利润仍为785元。当前商品毛利200元不减去全公司400元费用。

到“数据与下载”查看销售和退款明细。全部范围的退款前销售为4150元、当月退款910元，净收入为4150−910=3240元。退款根据退款确认日进入当月，并沿用原销售的商品、渠道和区域。

小样本没有完整上月、上年同月和本年1—8月，因此正常环比、同比和年度累计显示“—”。切回完整模拟数据后，再学习完整历史的比较。

## 5. 更换来源与连接数据库

### 完整文件与异名文件

“完整模拟数据”覆盖2024年1月至2026年9月。“异名模拟数据”使用另一套表与字段名称，通过阶段5配置转换成同样的标准事实。

先在完整来源记下2026年9月全部范围的结果：净收入267927.12、净成本165822.96、毛利102104.16、公司费用60504.74、经营利润41599.42元。切换到异名来源，重新选择同一月份与筛选，应得到相同数字。

切换来源会清除旧数据快照、月份和业务筛选，再读取新来源。请重新核对页面上方范围；这样可以避免上一来源的条件或结果混进下一来源。

### 本机MySQL

选择“本机MySQL小样本”，在左侧连接表单核对主机127.0.0.1、端口3306、数据库`finance_bp_stage3`以及用户名。本地输入MySQL密码，然后点击“读取 / 刷新数据库”。页面只读取来源表，不创建或导入数据。密码在本次读取完成后清除，不写入配置、结果或文件。

连接成功后，页面操作与文件模式相同，先核对小样本的3240、2055、1185、400、785。数据库业务数据更新后，需重新输入密码并点击读取按钮，才会取得新的快照。

“本机MySQL完整数据”对应`finance_bp_demo`。如果你尚未执行阶段5的完整数据导入，请先在PowerShell运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File '.\scripts\run_stage5.ps1' -Mode mysql-import
```

这一步把完整模拟文件装入项目演示库；运行成功后，再回到页面选择完整MySQL来源读取。阶段7的临时MySQL验证已完成，但不表示你这台电脑3306上的完整演示库已经装好。

### 自定义来源

选择“自定义配置”，上传阶段5格式的JSON配置。文件来源由配置给出文件路径；MySQL来源由配置给出非敏感连接项和表、字段映射，密码仍在页面表单输入。

可参考`configs/demo_renamed_files.json`或`configs/demo_renamed_mysql.example.json`。在“数据与下载 → 字段映射与校验”查看原始字段到标准字段的映射、标准对象记录数和口径说明。

当前页面展示并执行已明确的映射，不自动猜测企业字段含义。首次接入要确认金额是否含税、是否已扣退款、成本是否历史成本、日期采用哪种确认口径，以及实际覆盖范围。映射与口径在配置中调整后重新读取。

## 6. 识别0、未知和不适用

| 情况 | 页面表现与含义 |
|---|---|
| 完整月份、来源齐全、筛选内没有交易 | 收入和毛利为0；分母为0时比率为空 |
| 未加载、未来月份或只有部分实际事件 | 常规实际为空；已知事件可供明细核对，不冒充完整月 |
| 缺历史成本 | 收入可保留，成本、毛利与经营利润为空 |
| 未提供退款来源 | 退款前销售可保留，净收入和净成本未知 |
| 未提供费用来源 | 公司费用和经营利润未知；已有费用来源且完整月无记录，费用才为0 |
| 某实际维度缺预算或所选期间缺预算 | 合计预算与完成率为空，不以部分预算代替完整预算 |
| 有真实零预算 | 预算保留0和金额差异；完成率为空 |
| 上月或上年同月缺失、基数为0或负数 | 常规增长率为空，不跳到其他有交易月份比较 |

“—”不统一代表0。先看页面提示、覆盖范围和来源说明，再决定是未知、没有有效分母，还是该指标不适用于当前范围。完整模拟数据截至2026年9月；未来月份可以有预算，本阶段还没有预测实际。

## 7. 下载与页面显示有什么关系

下载采用当前月份或趋势起止月份、当前筛选及当前预算版本。文件名包含企业、期间、内容、范围及来源快照标识；预算比较还包含版本。公司费用下载采用公司全部范围。

CSV始终保存原始元金额，保留Decimal精度，不使用图表的浮点数或万元显示值。CSV含UTF-8 BOM，便于Excel直接读取中文；比例保留原始小数，例如0.9586代表约95.86%。未知值是空字段，真实0仍是0。

销售、退款与公司费用明细包含来源是否已提供、期间完整性及范围标记。文本型字段可能增加一个前导单引号，供表格软件把内容按文本读取；数值型负金额保留负号。

在“数据与下载”同时下载“明细范围与完整性说明（JSON）”。其中记录企业、规则、来源指纹、覆盖范围、筛选、各明细记录数与来源状态。尤其是空CSV只有表头，无法单独表达“完整零记录”或“来源未提供”；应结合JSON和带状态的文件名判断。

“经营总览”的当前结果JSON包适合复核实际、同比环比、累计、预算和维度结果。金额在JSON中保存为精确文本，未知保存为`null`。

## 8. 代码阅读顺序

1. 阅读`app.py`：找到来源选择、筛选控件、五个页面和下载入口，理解一次页面操作如何形成参数。
2. 阅读`src/analysis/service.py`的`analysis_pack`：观察月份、筛选、版本如何交给统一引擎，以及当前范围和公司范围如何分别返回。
3. 阅读`src/dashboard/view_model.py`：重点看`detail_tables`、`monthly_trend`、`budget_rows`、`chart_frame`、`csv_bytes`，理解精确数据如何变成表格、图表与下载。

页面负责组织条件和展示；财务公式继续由阶段6的`FinancialEngine`与比较函数提供。修改图表颜色、排序或显示单位时，不需要再写一套收入、毛利或预算公式。

三个概念值得记住：Streamlit控件接收你的选择；数据快照表示某次读取取得的标准事实；展示副本可以转换图表数字，但原始金额和下载仍保留精度。数据库刷新是重新读取数据，切换月份则是在当前快照上重新计算。

## 9. 三分钟演示练习

1. 打开小样本2026年9月总览，说明3240元收入来自4150元销售减去910元退款。
2. 选P001、C02、R02，说明200元是该组合毛利，而785元仍是全公司经营利润。
3. 打开预算比较，说明公司费用实际400元、预算380元，超支20元，因此方向不利。
4. 打开退款明细、选10月，说明跨月退款进入10月，但只有一个事件，完整实际仍未知。
5. 切换完整模拟数据、查看月度趋势，再切换异名来源，说明映射后的财务口径与结果一致。

能够完成这些操作并解释范围、精度和未知值，就具备进入阶段8的基础。下一阶段加入PVM与预算差异驱动拆解；预测和情景分析在后续阶段继续完成。
