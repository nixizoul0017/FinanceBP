## 3. 在现有MySQL上运行

打开PowerShell，执行以下两行：

```powershell
# 将下一行替换成自己电脑的项目目录
Set-Location -LiteralPath '<项目目录绝对路径>'
powershell -NoProfile -ExecutionPolicy Bypass -File '.\scripts\run_stage3.ps1'
```

MySQL提示输入密码时，在本机输入root账号密码。这个输入不应回显，也不会保存到项目文件。ExecutionPolicy Bypass仅用于这次PowerShell进程运行，不修改全局执行策略。

若使用其他MySQL账号：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File '.\scripts\run_stage3.ps1' -UserName '你的实际用户名'
```

账号需要能创建项目库、建表、插入查询数据，以及创建和删除本阶段自己的测试存储过程。没有这些权限时保留错误输出，按具体问题处理，不自行重置账号或现有数据库。

首次执行创建`finance_bp_stage3`。该名称已存在时停止，不覆盖旧库；需要再次练习可用`-DatabaseName finance_bp_stage3_practice2`创建新练习库。不要使用--force忽略错误；发生错误后日志会说明停在哪里。

## 5. 建表语句怎样读

订单明细里的几个片段：

```sql
quantity INT NOT NULL,
unit_list_price DECIMAL(18,2) NOT NULL,
discount_amount DECIMAL(18,2) NOT NULL DEFAULT 0
```

意思是：数量为整数且必填；售价为精确金额且必填；明细折扣允许明确无折扣时使用0。不是把缺失的关键金额都填为0。

```sql
PRIMARY KEY (order_item_id),
UNIQUE KEY uk_items_line (order_id,line_number),
CONSTRAINT fk_items_order FOREIGN KEY (order_id) REFERENCES orders(order_id)
```

意思是：明细ID唯一；同一个订单的行号不能重复；订单必须存在。所有正式表都有导入批次引用，先建批次，再建业务表。

CHECK校验同一行数量、金额、日期与状态；累计退款不超原销售金额需要03中的跨表汇总检查，数据库外键不自动完成这个任务。

## 6. 插入与事务怎样读

INSERT先列出字段，再按相同顺序给VALUES。02中的数据一次放入事务：

```sql
START TRANSACTION;
-- 插入样本
COMMIT;
```

COMMIT提交数据。自动测试故意插入错误场景时使用ROLLBACK撤销有效插入的测试记录，不污染业务样本。建表DDL与样本DML分开；不能认为ROLLBACK会把此前创建的表全部撤销。
