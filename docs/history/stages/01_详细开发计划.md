# 详细开发计划

> 阶段原始档案：保留当时的任务、决定和验证记录。当前使用方法见[使用指南](../../USER_GUIDE.md)，持续更新见[项目日志](../../PROJECT_LOG.md)。文中的阶段输出路径属于历史记录。


## 1. 项目要解决什么问题

项目名称：电商企业经营分析与预算预测平台。

模拟企业：星辰优选，一家自营销售家居生活用品的电商企业。企业拥有多个商品、销售渠道和区域，需要每月判断经营结果、解释预算偏差，并预测后续业绩。

项目服务三类用户：

| 用户 | 主要问题 | 系统输出 |
|---|---|---|
| 财务BP | 收入和利润为什么变化？预算为什么没完成？ | 月度指标、预算差异、驱动因素和经营点评 |
| 业务负责人 | 哪些商品、渠道和区域表现较弱？如何调整？ | 收入与毛利明细、排序、情景测算 |
| 管理层 | 全年预计能完成多少？哪些问题需要行动？ | 全年预测、风险与机会、月度经营报告 |

最终成品是一个可以在浏览器操作的应用：选择月份、渠道和区域，查看收入、毛利和费用，比较预算，解释变化，调整假设并导出月报。代码、文档、模拟数据说明和演示案例组成求职作品。

项目需要回答四个连续问题：发生了什么 → 差异由哪些数字因素构成 → 后续可能怎样 → 应当调查或采取什么行动。

## 2. 第一版边界

### 必须完成

- 模拟数据导入、校验、异常记录、重复导入保护。
- 月度收入、销售成本、毛利、费用、管理口径经营利润。
- 商品、渠道、区域分析；同比、环比、累计表现。
- 实际与预算比较，以及价格、销量、产品结构和退款的差异桥。
- 可解释的滚动预测、基础/乐观/谨慎情景。
- 浏览器页面、Excel月报、基于已计算指标的经营点评。
- 一套能够独立复核的样本与演示流程。

### 完成核心流程后再评估

现金流、库存、应收账款、客户LTV、复杂营销归因、机器学习、自动生成PPT、多用户登录、在线部署、Power BI、Docker。

第一版所有商品使用同一种销量单位“件”。默认金额为人民币不含税金额，采用项目自定义的管理分析口径。只展示已建模的管理口径经营利润；净利润需要额外建立税费、财务费用等项目后才加入。

### 模拟数据范围

- 历史实际：2024年1月至2026年9月，共33个完整月份。
- 当前年度预算：2026年1月至12月；保留预算版本。
- 预测时点：截至2026年9月，预测2026年10月至12月。
- 起步样本：3个商品、10个订单，包含取消和退款案例。
- 完整演示目标：20个商品、3个渠道、4个区域、约5万条订单明细。
- 数据规模可以调整；历史长度和日期边界应保持一致。2026年10月以后不得作为当前已知实际数。

先用小样本走通逻辑，再扩大数据。模拟数据包含季节性和预设业务变化，数据生成规则与预设原因单独记录；分析时据此检验模型能否找到对应变化。

## 4. 阶段1：明确业务规则和需求

**学习目标**：理解订单数据如何形成管理报表，区分下单金额、确认销售收入、退款、毛利和经营利润。

**实施顺序**：

1. 写清楚公司卖什么、在哪些渠道卖、管理层关注什么。
2. 列出5个管理问题，例如“收入增长但毛利下降，来自哪些商品？”
3. 定义确认销售、取消订单、折扣、退款、销售成本和费用归属规则。
4. 确定预算与实际比较的共同粒度。
5. 手算至少3个正常/取消/退款案例，记录原始数字与结果。
6. 把所有假设放进业务规则文档，标记已确认和待调整事项。

**交付物**：`docs/reference/business_rules.md`、`docs/reference/requirements.md`、`data/sample/手算样本.csv`。

**验收条件**：能用自己的话解释收入、退款和毛利；每个管理问题能指向所需字段；手算结果能够重现。

**求职表达练习**：用2分钟解释业务背景，以及这个系统支持什么决策。

## 5. 阶段2：设计数据库

**学习目标**：理解一行数据代表什么，掌握主键、外键、一对多关系和唯一约束。

**实施顺序**：

1. 从商品、客户、订单、订单明细开始画关系。
2. 增加退款和费用表，并写明各自的一行含义。
3. 设计月度销售预算和月度费用预算，保留版本字段。
4. 写数据字典：字段、类型、含义、是否允许为空、取值示例。
5. 检查历史商品成本是否保存于成交明细，避免后来调价改写历史。
6. 规划日期、渠道、区域的编码与校验，约定金额精度。

**交付物**：完善 `docs/reference/database.md`，形成正式数据字典和关系图。

**验收条件**：订单能够有多条明细；同一明细能够有多次退款；商品、订单、明细之间不会出现失效引用；销售预算可以与实际聚合至同一粒度。

**求职表达练习**：解释为什么订单和订单明细分表，以及为什么不能只存当前商品成本。

## 6. 阶段3：SQL建库、建表与导入样本

**学习目标**：会执行CREATE TABLE、INSERT、SELECT，理解约束对数据质量的作用。

**实施顺序**：

1. 检查现有MySQL和数据库客户端；优先使用已有环境，确认版本后选择适配语法。
2. 创建项目专用数据库，按父表到子表顺序建表。
3. 用SQL插入3个商品、少量客户和10个订单及明细。
4. 加入取消、部分退款、跨月退款、只有补偿无退货的案例。
5. 插入少量月度费用与预算。
6. 尝试重复主键、无效商品引用、超额退款，确认数据库约束或校验查询能识别问题。
7. 保存建表脚本、样本脚本和校验查询；在独立练习数据库验证重建步骤。

**交付物**：`sql/01_create_tables.sql`、`sql/02_seed_sample.sql`、`sql/03_quality_checks.sql`、环境记录。

**验收条件**：样本可查询；非法记录能被识别；文件中的脚本能够重新建立样本；退款累计量不超过原成交数量，退款金额不超过原折后收入。

**求职表达练习**：解释建表规则如何防止重复或错误的数据进入分析。

## 7. 阶段4：先用SQL回答经营问题

**学习目标**：掌握JOIN、GROUP BY、CASE、日期聚合和窗口函数，用SQL完成分析。

**实施顺序**：

1. 关联订单与明细，计算折后成交收入和成交成本。
2. 将销售按确认月份汇总，将退款按退款确认月份汇总，再在共同粒度合并。
3. 按月计算收入、成本、毛利；费用先单独汇总再合并。
4. 分别按商品、渠道、区域计算收入与毛利排名。
5. 构建完整月份序列，计算同比、环比、年度累计；缺少历史基期时显示空值。
6. 将实际与预算各自汇总至共同粒度，做基础差异比较。
7. 抽查明细、分组结果与总额；保存一份基准结果。

**交付物**：`sql/04_monthly_analysis.sql`、`sql/05_dimension_analysis.sql`、`sql/06_budget_analysis.sql`、基准CSV。

**验收条件**：至少独立完成6个查询；SQL结果与手算样本精确到分一致；每条JOIN都能说明连接前后的行数；多次退款不会把成交收入重复累加。

**求职表达练习**：讲清一条从订单明细到月度毛利的SQL查询。

## 8. 阶段5：Python读取、清洗和导入

**学习目标**：掌握函数、DataFrame、日期转换、缺失值处理、merge、groupby和数据库连接。

**实施顺序**：

1. 确认Python环境，创建项目环境，记录实际安装的依赖版本。
2. 先读取阶段4的JSON基准与同一套JSON样本，再读取完整CSV，练习筛选、类型检查、汇总与关联。
3. 建立MySQL连接，读取同一批样本，核对读取记录数和金额。
4. 实现字段检查、日期解析、重复记录识别、ID引用检查、金额与数量检查。
5. 将坏数据输出至异常记录文件，并记录处理原因；关键金额缺失时不自动填零。
6. 建立导入批次与唯一键，做到重复导入不会重复累计，失败批次可追踪。
7. 生成更大规模模拟数据，固定随机种子，保留生成参数与业务变化说明。
8. 将“读取→校验→清洗→导入→记录结果”整理为可调用流程。

**交付物**：练习Notebook和学习脚本、`src/etl/`中的处理模块、`scripts/generate_demo_data.py`、配置与数据质量报告。阶段5已实现的运行方法和证据见15、16文档。

**验收条件**：同一文件导入两次后有效数据量和金额不变；坏日期、重复ID、未知商品能被定位；正确数据进入数据库；SQL与Python汇总保持一致。

**求职表达练习**：解释为什么某条错误数据被隔离，以及如何追踪处理结果。

## 9. 阶段6：建立统一财务计算模块

**学习目标**：把一次性分析拆成能复用、能核对的函数；理解金额精度和筛选范围。

**实施顺序**：

1. 将收入、退款、成本、毛利和费用计算写成独立函数。
2. 加入同比、环比、累计和基础预算差异计算。
3. 统一输入参数：期间、商品、渠道、区域、预算版本。
4. 区分公司经营利润与商品/渠道毛利；共同费用保持公司级，未经分摊不显示商品净利润。
5. 用手算样本和SQL基准验证Python结果。
6. 为重要财务恒等式和易错边界建立少量自动验证。

**交付物**：`src/analysis/metrics.py`、`src/analysis/comparison.py`、核对记录和必要的财务测试。

**验收条件**：收入减成本等于毛利；公司毛利减费用等于管理口径经营利润；筛选后的明细与汇总可核对；零分母、空期间、跨月退款有明确输出。

**求职表达练习**：展示一个函数的业务含义，并说明它如何得到可信结果。

## 10. 阶段7：做出可操作的网页

**学习目标**：学会用Streamlit展示已有计算，用Plotly表达趋势、比较和结构。

**实施顺序**：

1. 先建立入口和一页经营总览，再扩展页面。
2. 总览显示收入、毛利、毛利率、公司经营利润及基础预算表现。
3. 增加月度趋势、商品/渠道/区域分析和数据明细。
4. 增加月份、渠道、区域筛选，所有图表使用同一筛选范围。
5. 页面显示单位、管理口径、实际数据截至月份、预算版本和数据更新时间。
6. 没有数据时显示说明；缺少预算时不把差异显示为零。
7. 增加明细导出，并在本地浏览器走一遍管理问题。

**交付物**：`app.py`、`src/dashboard/`、页面截图、启动说明。

**验收条件**：可在本地启动；更换筛选条件后指标、图表、明细和下载一致；页面金额能回到数据库核对；图表中的分组之和与总额一致。

**里程碑A**：形成一个可演示的“数据导入→财务指标→网页分析”版本。

**求职表达练习**：3分钟演示公司整体表现，并定位一个具体商品或渠道的问题。

## 11. 阶段8：预算差异和经营驱动因素

**学习目标**：从“差多少”深入到“差异由什么组成”，掌握预算粒度与PVM拆解。

**实施顺序**：

1. 固定预算版本，按月、商品、渠道、区域将实际与销售预算对齐。
2. 展示金额差异、差异率、完成率；为收入和费用分别定义有利/不利方向。
3. 对同一商品集合拆解销量、结构和价格影响；折扣已经进入净售价，不再重复加折扣影响。
4. 将退款差异单独连接到净收入差异。
5. 新增或停销商品单列；第一版先以固定商品集合完成标准PVM。
6. 构建瀑布图，点击差异可查看明细。
7. 增加毛利和费用差异分析；每个桥接模型写清顺序、公式和范围。

**交付物**：`src/analysis/variance.py`、`src/analysis/pvm.py`、预算页面、差异说明案例。

**验收条件**：销量+结构+价格+退款差异等于净收入总差异，计算未四舍五入前可核对，展示误差不超过0.01元；预算为零时差异率为空；不会拿月度预算直接关联订单后重复累加。

**里程碑B**：能完整演示“实际低于预算→哪一维度贡献最大→数字因素组成→建议进一步调查什么”。

**求职表达练习**：解释产品结构为什么影响收入，以及数学分解为何不能单独证明业务因果。

## 12. 阶段9：滚动预测与情景模拟

**学习目标**：区分预算、实际与预测，理解预测假设、历史回测和情景测算。

**实施顺序**：

1. 固定实际截止月份，已结束月份用实际，未来月份用预测。
2. 建立两个基准：上年同月值、最近完整月份均值。
3. 建立业务驱动预测：销量×折后净售价，再预测退款、单位成本和费用。
4. 用历史数据在多个截止点回测，严格只使用截止点前已知数据。
5. 比较MAE和WAPE，记录模型在哪些月份偏差较大；选择有依据的方案。
6. 保存预测版本、假设、截止月和生成时间。
7. 增加价格、销量、单位成本、退款率、营销费用等情景参数。
8. 生成基础、乐观、谨慎结果，显示全年预测与预算的差额。

**交付物**：`src/analysis/forecast.py`、`src/analysis/scenario.py`、回测记录、预测页面和假设表。

**验收条件**：全年预测=截止月累计实际+剩余月份预测；没有使用未来数据；零调整情景等于基础预测；价格和销量联动按乘法计算；费用变化能够正确影响利润。

模型是否足够好由回测和业务用途判断，第一版不预先承诺准确率。价格变化后的销量变化由用户输入假设；未估计需求弹性前不自动宣称提价一定增利。

实施状态：阶段9已完成三种方法、6个季度截止点配对回测、四套情景、页面和本地JSON不可覆盖版本。125项完整回归、临时MySQL3,648项数值核对通过；指南和证据见23、24文档。三张预测表设计保留为后续专用结果库方案，当前未建表。下一阶段为经营点评与Excel月报，用户学习确认仍独立记录。

**求职表达练习**：解释预测假设、误差和情景结果的适用边界。

## 13. 阶段10：经营点评和月报

**学习目标**：把数字转换成有依据的管理语言，并使报告可复核。

**实施顺序**：

1. 先用固定模板输出结果、差异、贡献维度、风险和调查建议。
2. 建立结构化指标包，包含期间、筛选、实际、预算、PVM和预测假设。
3. 如接入大模型，在本阶段查阅所选服务官方文档并确认接口、凭据及调用费用，密钥只在本地配置。
4. 大模型接收已计算的结果，输出解释；主要数字由程序核对后才展示。
5. 区分“数据显示的现象”“模拟数据预设原因”“待验证的业务假设”。
6. 无接口或调用失败时保留模板报告。
7. 导出Excel月报：总览、实际与预算、维度明细、PVM、预测假设、点评与口径说明。

**交付物**：`src/reporting/`、可选`src/ai/`、样本月报和事实核对记录。

## 17. 每一轮如何与AI合作

1. 先阅读本阶段目标和上一阶段验收结果。
2. 一次只处理一个具体任务，例如“建商品和订单表”或“完成月度毛利查询”。
3. 先解释输入、输出、业务含义，再实现。
4. 自己完成一个小练习：改筛选条件、手算一条明细或解释一条JOIN。
5. 运行并核对结果，记录问题和修正。
6. 勾选清单，保存成果，并明确下一任务。

完成某阶段前，至少能回答：输入是什么？输出是什么？业务规则是什么？怎样证明结果正确？若还解释不清楚，先补充练习，再进入下阶段。

## 18. 主要风险与处理方式

| 容易出现的问题 | 处理方式 |
|---|---|
| JOIN导致收入、退款或预算重复累加 | 明确表粒度，先分表汇总，再连接，核对行数与总额 |
| 商品调价改变历史成本 | 明细保存当时成本快照 |
| 公司费用被重复分摊到每个商品 | 第一版保持公司级费用；展示商品毛利 |
| 数据全部正常，无法证明模型价值 | 生成可解释的异常和变化，保留预设变化清单 |
| 预测看起来准确却使用未来数据 | 固定截止月并历史回测 |
| AI输出无法核对 | 结构化指标包、程序核数、模板备用 |
| 会运行但讲不清楚 | 每阶段完成手算、查询解释和求职表达练习 |
