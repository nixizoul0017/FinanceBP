## 1. 与阶段5有什么不同

阶段5负责把不同来源转换为可信的标准数据。阶段6负责在同一标准数据上计算财务指标。下一阶段网页只负责选择条件和展示，复用本阶段函数。

```mermaid
flowchart LR
 A[阶段5标准事实] --> B[FinancialEngine财务快照]
 C[月份/商品/渠道/区域/预算版本] --> B
 B --> D[实际/趋势/累计/预算]
 D --> E[统一结果包analysis_pack]
 E --> F[后续网页和报告]
```

计算不依赖orders等企业原表名，不直接执行建库或导入。文件模式不需要MySQL；选择MySQL来源时通过阶段5只读适配器取数。

## 5. 本阶段要学习的Python知识

### 输入、函数与返回值

从`scripts/stage6.py`阅读入口，再看以下函数：

| 位置/函数 | 输入 | 输出与用途 |
|---|---|---|
| `FinancialEngine(facts)` | 一家企业的标准事实 | 财务快照，保留精确金额、来源和完整覆盖范围 |
| `Filters(...)` | 商品/渠道/区域编码 | 统一筛选条件 |
| `summary(start, end, filters)` | 月份区间和筛选 | 收入、成本、毛利、比率及适用范围 |
| `monthly(start, end, filters)` | 起止自然月 | 连续月份DataFrame，缺月份也保留 |
| `dimensions(..., by=...)` | 区间和分组字段 | 商品、渠道、区域或组合汇总 |
| `trend_comparison(...)` | 所选月与筛选 | 环比和上年同月比较 |
| `year_to_date(...)` | 所选月与筛选 | 本年1月至所选月、上年同区间及比较 |
| `sales_budget_comparison(...)` | 区间、版本、筛选 | 销售预算明细、差异、完成率及缺预算记录 |
| `company_budget_comparison(...)` | 区间与版本 | 公司销售、费用和经营利润预算比较 |
| `analysis_pack(...)` | 财务快照与条件 | 后续网页统一调用的结果包 |

函数名表达任务，参数表达条件，返回值表达计算成果。把函数分开后，修改展示样式不需要重写财务公式。

engine = FinancialEngine(load_facts('configs/sample_files.json'))

### 为什么需要独立退款事件

metrics.py将销售和退款分别形成事件：销售提供正收入/正成本，退款提供退款额和成本转回。退款从原销售明细查商品、渠道和区域，但不再次复制销售额。

汇总时：净收入=销售收入−退款；净成本=成交成本−成本转回；毛利=净收入−净成本。商品比率由该商品汇总值相除，公司比率由公司汇总值相除，不平均商品毛利率。

## 6. 重点边界

| 情况 | 输出 |
|---|---|
| 已声明完整月，没有交易 | 收入/成本/毛利为0，比率为空 |
| 未完整载入某月 | 正常指标为空；已知行可在observed_metrics查看 |
| 上月缺失/零/负基数 | 常规环比为空；两期金额都已知时仍保留差额 |
| 年初到当前月有任何缺月 | 正常YTD为空，不以已知几个月冒充全年累计 |
| 净收入<=0 | 保留收入、成本和毛利金额，常规毛利率为空 |
| 当前范围存在缺成本 | 收入保留；净成本、毛利和利润为空 |
| 缺退款来源 | 退款前销售可保留，净收入与净成本未知 |
| 费用来源存在但记录为空 | 完整期间费用0 |
| 没有费用来源 | 公司费用及经营利润未知 |
| 有零预算记录 | 保留预算0和金额差异，完成率为空 |
| 实际维度缺预算，或区间中缺某月预算 | 相应合计预算为空，输出missing_keys/missing_months |
| 预算单位成本缺失 | 收入预算仍可用；成本、毛利、利润预算未知，cost_status说明原因 |
| 公司共同费用 | 在公司汇总一次，维度毛利不减共同费用 |

完整覆盖范围由接入者确认，不根据“有日期表”或“出现交易”自动推断。若某范围中仍有未载入月份，可在coverage里声明incomplete_months，例如["2026-08"]；比较时按自然月保留空缺，不跳过它取更早的有交易月份。

费用和退款是否已提供来源，由阶段5的data_availability记录。手工构建标准事实时也必须明确这一点；“未接入”和“已接入但为零”含义不同。
