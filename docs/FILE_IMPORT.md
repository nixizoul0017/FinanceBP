# 导入Excel、Stata及其他业务文件

**1.2.0默认流程已升级：**选表头行→勾选全部候选中的任意分类→改名→确认导入。下文的财务字段对应仅在“同时设置财务分析（可选）”开启时需要。普通分类导入和数据库列名接入见[按表头勾选分类](HEADER_CATALOG.md)。

**1.2.1修正：**销售编号默认合并为一个选择；支付时间等带时分秒的日期可以直接导入，无需先在Excel删除时间。

**1.2.2首次导入优化：**识别到订单、日期和金额时默认推荐财务设置、数据月份及少量分类，仍须确认。未选择数量列时每条明细默认1；单日/部分期间数据可以进入文件内已知交易分析，无需假称完整月。

从1.1.0起，“自定义配置”提供直接上传业务文件的入口，不必先编写JSON。当前[1.2.2体验版](https://github.com/nixizoul0017/FinanceBP/releases/tag/v1.2.2-rc.1)包含业务导入、加载遮罩修复及后续编号、日期、数量默认改进；历史1.0安装器不包含此功能。

## 操作步骤

1. 左侧“数据来源”选择 **自定义配置**，接入方式选择 **上传业务数据（Excel / DTA 等）**。
2. 点击 **选择业务文件（可多选）**。桌面版弹出系统文件窗口；可同时选择销售、退款、费用及预算文件。一个Excel包含多个工作表也可以。
3. 填写企业与接入名称。识别到订单表时会推荐财务设置，并按全表日期填写月份；首次默认勾选“这是单日或部分期间数据”。只有确认整月全部实际已提供时，才取消勾选并声明完整月。
4. 依次选择各类业务对应的文件/工作表，检查最多20行预览。必要时调整表头行。核对自动推荐的字段映射，也可手动选择名称不同的列。
5. 选择并确认销售部门、销售员、门店等附加分类。推荐仅用于辅助识别，业务含义由用户确认。
6. 核对人民币元、不含税、数量为件、销售金额为折后退款前金额等口径，点击 **验证并应用业务数据**。通过全量校验后进入原来的九个分析页面。

修改文件或映射时，原分析数据暂时保留。验证失败不会替换原快照，点击“取消导入修改，返回已应用数据”可返回。已成功接入的配置会保存至本机，下次在“继续使用已保存的文件接入”中选择，不必重复映射。

## 支持的格式

| 格式 | 规则 |
|---|---|
| Excel `.xlsx`、`.xls`、`.xlsm` | 选择工作表；表头行可在1—100行内调整；不执行宏。公式须先在表格软件中计算并保存，读取其已保存结果 |
| Stata `.dta` | 读取数据、日期及变量标签；保留原始编码，不把数值标签替换成编码。Unicode数据建议118/119格式 |
| CSV `.csv`、TSV `.tsv` | 分别使用逗号、制表符；自动识别UTF-8、带BOM的UTF-16以及GB18030兼容文本 |
| 记录列表 `.json` | 每个对象为一条记录，字段为列；不支持单元格内嵌套对象 |
| 接入配置 `.json` | 使用“已有JSON配置（高级）”入口；原有MySQL和文件配置仍兼容 |

**文件格式和业务内容需同时匹配，不能只改文件后缀。** 单文件最多100MB，一次最多20个文件、总计200MB；每张表最多100万行、500万个单元格。请去掉与分析无关的大图和空格式区域。加密、损坏、重复/空白表头或Excel错误单元格会被阻止并提示。

文本编码中的前导零保留。Excel数值编码如果使用简单的全零格式（例如0000），会保留显示出的补零；复杂自定义编码请先将整列转为文本。Stata编码若原本存为数值，丢失的前导零无法凭空恢复。

## 需要哪些业务字段

当前导入面向已经确认的销售明细，不从含取消订单、未确认订单的混合流水中猜测收入。每张表一行对应一项业务，列名可以不同，但含义必须对应：

| 业务表 | 必需字段 | 可不提供 |
|---|---|---|
| 销售明细 | 订单编号（唯一明细编号）、销售确认日期、折后退款前销售金额 | 数量未映射时每行默认1；商品、渠道、地区缺失列入“未归属”；历史成本缺失保持未知 |
| 退款明细 | 退款唯一编号、原销售明细编号、退款日期、退货数量、可回库数量、退款金额、可冲回成本 | 无退款需明确选择“确认无此类记录” |
| 公司费用 | 费用唯一编号、发生日期、费用类别、金额 | 部门默认公司；渠道/地区范围默认ALL |
| 销售预算 | 预算版本、月份、数量、折后退款前单价、退款金额、成本冲回 | 原三分类可缺失；单位成本可缺失；仅金额预算使用预算工作台模板 |
| 费用预算 | 预算版本、月份、费用类别、金额 | 部门默认公司；渠道/地区范围默认ALL |

### 订单编号只选择一次

同一订单一行时，选择一次“订单编号（唯一明细编号）”即可。程序将同一原始列用于内部订单编号和唯一明细编号，不再报两项冲突；该列必须每行唯一。

同一订单有多条商品明细时，打开“同一订单包含多条明细（高级）”，分别选择可重复的订单编号及每行唯一的独立销售明细编号。退款关联原来的独立明细；普通模式则关联原订单编号。重复明细会被阻止并提示，不会自动合并、丢弃记录或重复计入金额。已有配置中的两个独立编号继续保留，编辑时恢复高级模式。

### 成交数量默认1

没有数量列时，将成交数量保留为“默认1（每条销售明细）”，无需在Excel手工新增列。这个数表示每条明细按1计数，不能由此认定一笔订单只含一件商品。选择数量列后以该列为准，空白、0、负数或非整数会阻止导入，不用默认1掩盖错误。原文件不变，接入配置、页面及月报会记录数量默认方式；预算数量不采用这个默认。

### 单日或部分期间也能分析

勾选“这是单日或部分期间数据”，开始与截止填写实际文件所属月份。例如单日流水只填该月份，程序将其标为不完整。进入分析页后展开“文件内已知交易分析”，可看已导入销售额、订单数、平均订单金额、已知退款及净收入；在顶部选择分析分组、应用后可按点位、部门或商户类型联合核对，并下载分类结果。

普通整月指标、预算完成率、同比环比及预测保持不可用，不以一日流水外推整月。缺成本时成本和毛利保留未知，缺费用时公司利润未知。只有文件退款列全部明确为0时，部分期间入口才推荐本次文件范围无退款，仍须用户确认；有正退款、空值或无法解析的值不会这样推荐。非零退款继续要求退款明细和发生日期，不从订单汇总退款额猜测事件月份。

推荐分类仍需首次核对，可取消、增加和改名；手机号等字段不会被自动推荐。订单金额只推荐对应销售金额，需确认实际含义和元/分单位，优惠券列不会再自动扣减。

### 支付时间和日期时间

“支付时间”“付款时间”“支付日期”等列名可自动推荐至销售确认日期；存在多个匹配列时仍由用户确认。支持`2026-10-21 9：20`（中文冒号）、`2026-10-21 09:20:30`、`2026/10/21 9:20`及Excel/Stata/数据库原生日期时间；原来的`2026-10-21`、`20261021`以及预算月份`2026-10`继续支持。

财务分析按来源中显示的日历日期归月，不因时区标记换算为另一天。日期和时间均校验，非法日期或`25:90`等无效时间会提示修正。只对已明确对应的业务日期做转换，原始文件和普通分类字段的值保持原样，不把数值编码猜测成日期。**将支付时间选为销售确认日期，表示用户确认该文件以支付日确认销售；系统不自行判断支付是否满足收入确认条件。**

没有提供某类表时选择“未提供”，不会自动认定为0；只有确认该期间确实无此类业务才选“确认无此类记录”。未提供退款来源时，净收入保持未确认；未提供费用时，公司经营利润保持未知。没有预算时不伪造预算，可在预算工作台另行编制。

金额默认严格校验至分，单价/单位成本至四位小数。Stata单精度浮点可能出现0.100000001等存储误差；核对原始数据后，可以明确勾选该表的“四舍五入”选项。此选项只调整读取后的分析值，不修改原文件，且会记在本机接入配置中。

退款仍必须关联原销售；校验唯一键、日期、累计退款、退货数量及成本冲回，禁止重复收入。期间超出截止月时须核对完整性后重新导入。历史原销售可以早于起始月，以支持跨月退款。

## 分类、预算与保存

附加分类初次绑定销售实际。预算也具备这些字段时，在“分类识别与映射”中另行确认预算字段、版本和粒度；没有销售员预算就不会生成销售员预算。费用部门也不会自动视为销售部门。关联独立员工资料表等复杂映射仍使用高级JSON配置和现有分类确认流程。

上传文件复制到个人数据目录的 `imports`，按内容摘要命名；接入配置保存在 `profiles/business_imports/*.local.json`。安装版根目录为 `%LOCALAPPDATA%\FinanceBP`，源码模式为项目 `outputs`。不同企业请使用不同企业/接入名称，避免串用分类方案。

备份包含已保存映射、方案和个人财务记录，**不包含业务文件**；换电脑时另外保存原始业务文件并重新选择。程序不会写企业源文件或MySQL。上传文件、本机接入配置及导入预览不进入公开源码包。

格式验收使用人工构造数据，包括 `tests/fixtures/business_import_legacy.xls`（xlwt 1.3.0生成的单行旧版Excel，只有虚构编号、日期和金额），不包含真实客户、员工或交易。
