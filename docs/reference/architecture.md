# 通用接入与最终产品设计

状态：阶段5—10已实现文件/MySQL读取、连接配置、字段映射、统一财务计算、网页、预算驱动、预测和月报。阶段11完成本机独立目录、新Python环境与临时MySQL重建，两环境各143项完整回归通过。另一台实体电脑迁移、复杂行业模板与其他数据库类型待继续验收。当前电商案例为第一个业务模板。

## 1. 最终产品形态

产品定位：可配置的经营分析与预算预测平台。以Python处理数据和计算，Streamlit提供浏览器页面。

第一版交付为Windows上可安装依赖并启动的项目包：程序代码、经过验证的依赖版本、启动入口、模拟数据、配置模板、操作说明与验收记录。启动后浏览器打开经营看板，后台Python程序连接数据源并执行分析。

后续需要多人使用时部署到企业内部服务器，用户从浏览器访问；后台服务持有连接与计算配置。是否需要桌面入口、容器或其他打包方式，在基本流程和迁移验收完成后确定。

数据库可以与程序位于同一电脑，也可以位于其他可访问服务器。新电脑上的localhost/127.0.0.1指的是新电脑本身；如果继续使用原电脑上的数据库，要配置原数据库主机地址并具备网络访问条件。

新电脑连接远程已有数据库时，需要程序运行环境和对应数据库驱动，不要求安装本地MySQL服务或Navicat。演示模式可直接读取随项目提供的模拟文件。

## 2. 将变化隔离为五层

```mermaid
flowchart LR
    A[企业数据源] --> B[连接与取数]
    B --> C[字段映射和业务适配]
    C --> D[标准分析数据]
    D --> E[财务计算模块]
    E --> F[浏览器看板和报告]
```

| 层 | 做什么 | 更换企业时怎样变化 |
|---|---|---|
| 连接 | 主机、端口、库、账号和驱动 | 换连接配置，凭据在本次读取输入或由运行环境提供 |
| 取数与映射 | 源表、字段、关联键、编码和粒度 | 换数据源配置；复杂源需要专用取数适配器 |
| 标准数据 | 统一销售、退款、费用和预算字段 | 财务模块接收一致结构 |
| 业务口径 | 确认日期、折扣、税口径、成本、退款与费用规则 | 选择或调整业务模板，保存规则版本 |
| 展示 | 指标、维度、期间、预测和导出 | 复用页面；按可用数据启用模块 |

数据库连接能力不自动完成字段或财务语义适配。[Streamlit数据连接说明](https://docs.streamlit.io/develop/concepts/connections/connecting-to-data)、[SQLAlchemy连接配置](https://docs.sqlalchemy.org/en/20/core/engines.html)

## 3. 字段名不同的映射例子

| 标准含义 | 企业A源字段示例 | 企业B源字段示例 |
|---|---|---|
| 销售明细身份 | order_item_id | sale_line_no |
| 销售确认日期 | recognized_date | revenue_date |
| 商品或分析对象 | product_id | sku_code |
| 销量 | quantity | sales_qty |
| 折后、退款前收入 | 数量×单价−明细折扣 | sales_amount_net |
| 销售成本 | 数量×历史单位成本 | booked_cogs |
| 渠道 | channel_code | sales_platform |

企业B的sales_amount_net只有在明确为相同税口径、退款前且已扣折扣时，才可直接作为对应标准收入。如果其已扣退款，适配器需要转换或使用另一种标准事实输入，避免再次扣退款。

一个标准概念可以映射到一个源字段，也可以通过源字段组合计算。字段推荐可以辅助匹配，但首次接入需要明确其业务含义、单位和粒度。

## 4. 标准数据契约

标准数据不要求企业修改自身数据库表名。取数后在程序或项目自己的数据区形成以下结构：

| 标准对象 | 核心字段与规则 |
|---|---|
| 销售 | entity_id、sale_line_id、revenue_date、product_id、channel_id、region_id、quantity、sales_amount_before_refund、cogs_amount；一行一条确认销售明细 |
| 退款 | entity_id、refund_id、sale_line_id、refund_date、refund_amount、cost_reversal_amount；一行一次确认退款事件 |
| 费用 | entity_id、expense_id、expense_date、expense_category、department、归属与amount；共同费用不复制到销售明细 |
| 销售预算 | entity_id、budget_version、month、商品/渠道/区域、数量/价格/成本/退款假设或同口径金额 |
| 费用预算 | entity_id、budget_version、month、分类/部门/归属与金额 |

每个对象保留来源身份、数据截至日期、完整覆盖范围、币种与金额单位、规则版本。来自不同企业的业务ID只在企业范围内唯一，不能按相同订单号混合。

实际接入前确定去重键、连接行数、含税/不含税、折扣是否已扣、退款是否已净额化、日期含义及单位。验证原数据总额、标准数据总额和手工样本能对应。

第一版沿用人民币不含税销售模板。币种转换、复杂收入确认及费用分摊作为独立规则扩展，不能仅更改字段标签。

## 5. 业务模板与通用程度

第一版范围：MySQL数据源，以及类似商品销售、退款、费用和月度预算的经营场景；同时保留文件演示入口。

- 字段和表名变化：由映射与取数适配器处理。
- 已存金额与明细计算方式变化：由收入/成本来源规则处理。
- 完成日期与其他收入确认日期变化：由业务模板规定。
- 无预算：收入和毛利分析正常，预算模块显示缺少预算并停用相关比较。
- 无成本：收入分析正常，毛利/利润模块标明缺少成本，不默认成本为0。
- 只有月度汇总：可做对应粒度趋势和预算；不能宣称支持订单明细追踪。
- 商品单位不同：PVM只在可比较单位或业务分组内使用；不能将件数、服务工时等直接相加拆销量。

后续可增加服务项目、门店等模板。服务企业的成本、收入确认、项目周期等规则需要重新定义；通用连接与标准模块可以复用，行业财务规则分别验证。

SQLAlchemy提供多种数据库方言的连接基础，但每种数据源仍需要驱动、取数语法和适配验证；第一版不承诺所有数据库都开箱即用。[SQLAlchemy引擎与驱动说明](https://docs.sqlalchemy.org/en/20/core/engines.html)

## 6. 新企业的接入流程

1. 创建企业/项目配置，设置连接地址、端口、库和本地凭据。
2. 测试连接并查看允许读取的表与字段。
3. 选择业务模板，映射字段、状态、单位与维度编码。
4. 预览小样本和关联行数，确认一行含义。
5. 运行质量检查和金额核对，显示未满足的条件。
6. 保存映射与规则版本，明确完整历史范围。
7. 启用能被现有数据支持的分析模块。

连接真实企业来源以读取为主；程序无需在对方业务库执行本项目建表或创建分析视图。复杂源先提供专用SELECT取数适配器，阶段4视图作为演示来源的一种已验证输入。

缓存与导出至少按企业/项目、连接配置身份、规则版本、期间和筛选隔离。切换企业后不得沿用上一企业数据缓存。

阶段7的实际入口是来源选择、阶段5JSON配置上传和MySQL连接表单。字段映射在配置中明确，页面显示映射与已校验标准记录；当前不自动猜测字段或提供行业模板向导。来源数据库只执行读取，建库和模拟数据导入使用阶段5独立入口。

网页为每个会话保留只读财务快照和有限结果缓存，计算身份包含企业、规则版本、来源内容指纹、月份、筛选与预算版本。来源切换会清除旧快照和筛选，读取失败也清除旧结果。文件刷新或MySQL显式刷新后重新校验内容；不会通过多个用户共用一个全局财务缓存。费用与公司利润继续独立于销售维度筛选。

下载文件名标明企业、范围、内容及来源快照；预算导出另标预算版本。CSV保存精确元金额，空明细配套JSON记录来源是否已提供、期间完整性、行数和筛选，避免把未接入来源误认成零记录。

## 7. 换电脑的迁移流程

1. 在新Windows电脑安装或准备经过验证的Python运行环境。
2. 放入程序包与非敏感配置模板，安装锁定的依赖。
3. 在新环境重新设置数据库连接凭据，或选择模拟文件模式。
4. 启动后台，浏览器打开应用。
5. 测试连接与标准数据校验，核对关键金额和报告。

程序包不携带用户数据库密码；连接参数来自配置而非固定开发电脑绝对路径。数据源存在其他服务器时，程序和数据库可分别部署。

## 8. 如何验证通用性

验证通用性的主要证据不是单一数据库里的数据行数，而是同一财务模块面对不同来源仍能得到同口径结果。

- 构造第二套表名和字段名不同的模拟来源。
- 第一套通过数量/价格/折扣计算收入，第二套提供已计算同口径金额。
- 经各自适配后，同一组交易的标准销售、退款、成本和费用金额应一致。
- 同一个看板能够切换两套配置，金额与缓存互不串用。
- 缺成本、缺预算、不同单位时，模块按约定降级提示。
- 在独立环境重建运行，不依赖开发电脑特定路径或数据库名。

模拟数据规模用于检验完整业务分析、性能和历史模型；第二套来源和迁移验收用于证明配置与接入能力。两类验证同时保留。
