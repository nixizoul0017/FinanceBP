# 财务指标与模型口径

状态：阶段1手算确认的v1管理口径；基础指标、趋势、累计和基础预算比较在阶段6实现，阶段8已加入收入PVM、退款、毛利与公司利润桥。预测与点评仍按阶段9—10推进。SQL、Python与页面使用同一口径，证据见18、22验收记录。

## 1. 确认规则

- 默认公司为自营商品销售；金额人民币、不含税，货币单位在页面明确显示。
- 只有已完成、已确认的订单按recognized_date计入成交销售；取消和未确认订单不计入。
- 订单明细折扣保存为整条明细的金额，不能再乘数量。
- 退款按refund_date计入当期，归属原商品、渠道和区域，不修改过去月份。
- 销售成本使用成交时保存的成本快照。成本转回使用退款记录中经规则校验的金额。
- 公司经营利润为本项目管理指标：毛利减已建模费用，不包含尚未建模的税费、财务损益等项目。
- 费用依据确认日期归期；共同费用保持公司级。第一版不做商品层级共同费用分摊。
- 历史基期不存在时显示“无可比数据”，不伪造同比、环比或完成率。

## 2. 基础指标

| 指标 | 计算方式 | 注意事项 |
|---|---|---|
| 原价成交金额 | Σ数量×原价单价 | 仅确认销售明细；不可与净收入混用 |
| 折后成交收入 | Σ(数量×原价单价−明细折扣额) | 退款前的收入 |
| 净销售收入 | 折后成交收入−当期退款额 | 跨月退款可导致某维度当期净收入为负 |
| 成交成本 | Σ数量×单位成本快照 | 不读取当前商品成本 |
| 净销售成本 | 成交成本−当期成本转回 | 无退货补偿不转回成本 |
| 毛利 | 净销售收入−净销售成本 | 可以在商品、渠道、区域计算 |
| 毛利率 | 毛利÷净销售收入 | 净收入<=0时不展示常规比率，保留金额并标注 |
| 管理口径经营利润 | 公司毛利−公司期间费用 | 第一版只在公司级展示 |
| 已确认订单数 | 当期确认订单ID去重数量 | 订单多条明细仍只算一个订单 |
| 成交客单价 | 折后成交收入÷当期确认订单数 | 退款另列，避免跨月退款扭曲定义 |
| 成交销量 | Σ已确认销售数量 | 用于价格/销量/结构分析 |
| 净销量 | 成交数量−当期退货数量 | 只退款无退货时不减数量 |
| 折后平均售价 | 折后成交收入÷成交销量 | 退款前；只能汇总同单位商品 |
| 费用率 | 公司费用÷公司净销售收入 | 净收入<=0时为空 |

比率从汇总分子与分母计算，不能直接平均各商品毛利率。毛利率由30%变成28%，下降2个百分点，不能写成下降2%。

## 3. 手算校验样本

一条9月确认销售明细：数量10件，原价100元/件，明细折扣100元，成本60元/件。

- 折后成交收入=10×100−100=900元。
- 成交成本=10×60=600元。
- 9月内退回2件，退货退款180元，成本转回120元。
- 9月净收入=900−180=720元。
- 9月净销售成本=600−120=480元。
- 9月毛利=240元，毛利率=33.33%，净销量=8件。
- 若公司9月仅此交易且有费用100元，公司经营利润=140元。

如果这次退款在10月确认，则9月收入900元、成本600元、毛利300元；10月体现收入−180元、成本−120元、毛利−60元。只退款60元且无退货的补偿事件，收入减60元，成本转回为0。

阶段1已在[业务规则](business_rules.md)中补齐取消订单、多次部分退款和零收入案例，后续SQL与Python使用这些期待结果核对。

## 4. 趋势与预算

- 环比=(本月−上月)÷上月；同比=(本月−上年同月)÷上年同月。
- 常规增长率要求基期>0；基期为零、缺失或负数时显示金额变化和说明。
- 年度累计为本年起至所选完整月份，预算和上年比较使用相同月份区间。
- 差异额=实际−预算；预算>0时，差异率=差异额÷预算，完成率=实际÷预算。
- 收入、毛利、利润高于预算通常为有利；费用高于预算通常为不利。结论仍需结合业务背景。
- 预算为零时保留金额差异，比率为空；预算缺失时明确提示，不能当作零预算。
- 实际和预算先各自汇总至月×商品×渠道×区域，再连接。费用按自己的共同粒度比较。
- 如果某筛选仅支持销售预算、不能支持公司共同费用，应展示收入/毛利预算差异，并明确共同费用范围。
- 完整月覆盖由接入配置声明；已知零交易月与未载入月份分别处理。1月至当前月有缺月时，正常YTD保持未知。
- 费用/退款来源未提供不等于已知0；当前范围缺成本时毛利与利润未知，已接入且确认完整的零费用期间可按0计算。

## 5. 收入PVM拆解

第一版在固定商品集合、同一种数量单位下，对退款前的折后成交收入做价格、销量、结构拆解。退款差异单列。如此可避免退款造成负销量和不合理占比。

将一个比较范围内的商品编号记作i：

- q0_i、p0_i：基期/预算商品销量、折后单价。
- q1_i、p1_i：当期实际商品销量、折后单价。
- Q0=Σq0_i，Q1=Σq1_i。
- s0_i=q0_i/Q0，s1_i=q1_i/Q1。
- R0=Σq0_i×p0_i，R1=Σq1_i×p1_i。

选定按“总销量→产品结构→价格”的顺序拆解：

```text
销量影响 = (Q1−Q0) × Σ(s0_i × p0_i)
结构影响 = Q1 × Σ((s1_i−s0_i) × p0_i)
价格影响 = Σ(q1_i × (p1_i−p0_i))
退款影响 = −(当期退款额−基期/预算退款额)
净收入差异 = 销量影响 + 结构影响 + 价格影响 + 退款影响
```

该顺序把交互项分配到后面的因素；改变顺序可能改变各项贡献，所以同一报告始终使用相同顺序。折扣已经包含在p0/p1中，不再额外加入折扣差异。

### 可复核示例

| 商品 | 预算数量 | 预算单价 | 实际数量 | 实际单价 |
|---|---:|---:|---:|---:|
| A | 10 | 100 | 12 | 90 |
| B | 10 | 200 | 8 | 200 |

预算收入3000元，实际折后成交收入2680元。总销量都为20件，销量影响0元；结构影响−200元；价格影响−120元。若预算退款0元、实际退款80元，净收入差异为−400元，四项相加可核对。

边界：阶段8已将预算销量为0但本期有成交的商品、本期无成交但预算有销量的商品单列收入贡献，PVM仅用于双方都有正销量的共同集合。整个范围没有共同商品时，三项共同集合因素为0；不强行算占比，零销量商品的均价为空。缺预算键先阻止拆解，不能视为预算零销量。以上状态只描述所选期间与范围，不证明新上架或永久停销。

实际与预算先按月×商品×渠道×区域检查覆盖，再汇总至商品计算加权均价。均价贡献含折扣、渠道与区域成交组合变化，不能直接称为标价影响。

数学分解说明金额贡献，不证明“价格下降导致销量变化”等因果。真正业务原因需要活动、供应、定价记录或访谈证据。

## 6. 毛利差异桥

先做一个顺序明确且可核对的模型：

```text
净毛利 = Σq_i×(p_i−c_i) − 退款额 + 成本转回额
销量影响 = Σ(q1_i−q0_i)×(p0_i−c0_i)
价格影响 = Σq1_i×(p1_i−p0_i)
单位成本影响 = −Σq1_i×(c1_i−c0_i)
退款与成本转回影响 = −(F1−F0)+(C1−C0)
毛利差异 = 上述四项之和
```

其中c为单位成本，F为退款额，C为成本转回额。此模型中的商品销量变化已包含结构变化，不能额外把收入PVM结构金额再加入毛利桥。公司利润差异=毛利差异−期间费用差异。

阶段8的毛利桥也单列预算无销量商品的本期成交毛利、本期未成交商品的负预算成交毛利，再对共同商品使用上述公式。公司费用只进入公司利润桥，不随销售维度筛选分摊。

## 7. Forecast与情景

全年预测=截止月累计实际+剩余月份预测。预算保持原版本，Forecast保存独立版本。

预测优先以业务驱动字段输出：月度销量、折后净售价、退款额、单位成本、成本转回、费用。先比较上年同月与近期均值基准，再增加季节性、增长与管理假设。

回测仅使用历史截止点前可知信息。MAE=平均绝对误差；WAPE=Σ|预测−实际|÷Σ|实际|，分母为零时不计算；明确评估的是退款前收入、净收入或其他指标。

情景销量=q×(1+销量调整)，情景价格=p×(1+价格调整)，情景成交收入=Σ情景销量×情景价格。商品成本、退款和费用按各自假设计算。

例如价格+5%、销量−3%，收入倍率为1.05×0.97=1.0185，即增长1.85%。价格与销量不能简单相加。零调整且其他假设相同，结果必须回到基础预测。

阶段9实现：预测采用月×商品×渠道×区域，已知件数按非负ROUND_HALF_UP取整。近期均值先预测件数再乘最近销量加权单价/成本，因此不严格等同于金额均值；业务驱动采用上年目标同月销量×近期同比销量倍率，倍率限制0.5—1.8。缺历史正销量时使用近期均量，无完整历史时保持未知。

退款与成本转回按最近事件均值及成交收入暴露缩放，分别保存至分。业务驱动费用中佣金随成交收入、物流随件数，其余先用近期均值；情景可再调营销及所有费用。先件数取整再应用价格倍率，实际总倍率可能不同于连续数量例子。情景作用于公司全部业务，销售筛选只改变展示范围。

回测采用季度截止点及后续1—3个月，各方法用相同验证月份；公司净收入/毛利/经营利润选型目标可选，至少6个配对月份才按最小WAPE自动选型。预算仅用于预测结果比较，不参与训练。模型、预设、边界和默认误差见23指南，验证见24记录。

预测版本实际保存于outputs/stage9/runs的不可覆盖JSON，包含保存时间、假设、截止月、方法、训练/来源指纹、基础及情景引用。08的三张预测表仍为后续专用结果库设计，当前来源MySQL只读。

## 8. 金额精度与验证

- 入库和计算采用精确小数或整数分；不要默认数据库DECIMAL读取后仍保持精确小数，需检查连接与Pandas的转换行为。
- 平均单价、比率和模型中间结果保留足够精度，最终展示才四舍五入。
- 验证分为手算样本、SQL基准、Python结果和页面/报告核对。
- 核对明细与总额、分组和合计、收入成本毛利恒等式、预算/PVM桥、预测时间边界。
- 禁止默默丢弃错误记录或将关键缺失金额填零；异常必须可追踪。

阶段8分解涉及循环小数时，内部采用有理数检查精确恒等式，输出高精度Decimal与表示尾差；事实金额不改变。页面因素汇总另列显示至分的舍入尾差，该行只负责展示勾稽，不属于经营驱动。

## 9. AI点评规则

每条点评包含期间、事实数字、对比基期、贡献因素和调查建议。程序先完成计算，再生成指标包。

“华东区域贡献收入负差异的X%”需要明确是占净差异还是负向贡献总额；存在正负抵消时，优先展示贡献金额及占负向贡献比例。

没有业务证据时写“建议核实活动/供货/定价因素”，不把假设写成已证实原因。大模型输出中的主要金额、比率和月份需核对，错误结果不能直接作为最终月报。
