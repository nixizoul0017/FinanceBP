# 业务规则

状态：用户已确认理解的v1业务规则，作为SQL和Python实现的共同基线。阶段3—6的样本、完整模拟数据及统一财务计算已完成验证；后续调整同步记录，保持口径可追溯。

## 1. 业务背景与项目价值

星辰优选是一家自营销售家居生活用品的电商企业，通过3个渠道向4个区域销售20种商品。财务BP每月需要分析收入、毛利和费用，解释预算偏差，并预测全年结果。所有经营数据为模拟数据。

你将以企业财务BP的角色使用该系统，根据销售、退款、成本、费用与预算数据解释经营变化，分析盈利能力，支持业务负责人调整销售策略和成本投入。

仅有收入数字不能判断企业是否赚钱。收入增长可能伴随折扣增加、低毛利商品占比提高或营销费用上升，因此需要继续分析成本、毛利、费用和经营利润。系统帮助发现变化并测算调整方案；持续经营能力还需要现金流、偿债等信息，第一版不据此做完整判断。

## 3. 从交易到经营分析的流程

客户下单 → 记录订单和商品明细 → 完成销售确认 → 汇总收入与成交成本 → 加入当期退款及成本转回 → 形成净收入与毛利 → 减去当期费用 → 得到公司管理口径经营利润。

订单表示一次购买，订单明细表示其中的一种商品记录。一个订单可以有多条明细；同一条明细可以发生多次部分退款。退款和费用独立记录，避免关联时重复计算。

## 4. 销售确认、取消与折扣

| 规则编号 | 规则 | 对计算的影响 |
|---|---|---|
| BR01 | 第一版把订单完成日期定义为项目销售确认日期recognized_date | 收入和成交成本归到确认月份 |
| BR02 | pending未确认、cancelled取消订单不计入已确认销售 | 仍保留订单记录，但不计收入、销量与成交成本 |
| BR03 | completed订单已确认；后续退款不改成取消订单 | 历史成交保留，退款由单独事件反映 |
| BR04 | quantity为销售件数，unit_list_price为每件原价 | 原价金额=quantity×unit_list_price |
| BR05 | discount_amount是整条明细的折扣金额 | 折后成交收入=数量×原价单价−明细折扣额 |
| BR06 | 第一版折扣在订单明细记录，订单层优惠已分配至明细 | 不再从订单层重复减一次折扣 |

上述为模拟项目约定。下单日期、支付日期与确认日期可以不同，经营收入统计统一使用确认日期。

## 5. 退款与成本转回

| 规则编号 | 规则 | 对计算的影响 |
|---|---|---|
| BR07 | 只纳入已经确认的退款，按refund_date归期 | 当期净收入=当期折后成交收入−当期退款金额 |
| BR08 | 跨月退款在退款月份反映，不改写销售月份 | 单个商品当月可能有负净收入 |
| BR09 | 退货成本转回按原成交成本与实际可回库数量确定 | 当期净成本=当期成交成本−当期成本转回 |
| BR10 | 无退货补偿只减少收入；退货不可回库时不转回成本 | 不能看到退款就自动冲减商品成本 |
| BR11 | 一条明细可多次退款，累计退款额不超过原折后收入 | 分次记录，校验累计金额 |
| BR12 | 累计退货数量不超过原销售数量，成本转回不超过原成交成本与可回库成本 | 超额记录标为异常，不进入正式分析 |

退款金额和退货数量是两个不同字段：部分补偿可以有退款金额、退货数量为0。例子中的等比例退款只是样本设定，实际数据仍使用事件记录金额。

## 6. 成本、费用和利润

- **成交成本**：销售数量×成交时单位成本快照。后来采购成本变化，不修改历史成交成本。
- **毛利**：净销售收入−净销售成本。商品、渠道、区域可以计算毛利。
- **期间费用**：营销费、平台佣金、物流费、人工和管理费，依据费用确认日期计入。第一版物流等费用统一列为期间费用，不再重复放入商品成本。
- **费用归属**：能直接识别渠道/区域的记录保留归属；共同费用留在公司级。第一版公司费用全部纳入一次，不进行商品分摊。
- **公司管理口径经营利润**：公司毛利−公司期间费用。暂不包含税费、财务损益等未建模项目，不称为净利润。
- **筛选规则**：商品、渠道、区域筛选展示收入和毛利；经营利润保留公司全口径并明确标注，不将筛选毛利减去全公司费用。
- **零或负收入**：保留收入、成本和毛利金额；净收入<=0时不展示常规毛利率。

## 7. 比较、预算与预测规则

1. 同比与上年同月比较，环比与上一个自然月比较；同时需要确认期数据和退款期数据。
2. 累计为本年1月至所选完整月份；预算与上年累计使用相同区间。
3. 比率从汇总分子、分母计算，不平均各商品毛利率。
4. 月度销售预算粒度为月×商品×渠道×区域；费用预算按月×费用类别×部门×归属记录。
5. 预算与实际各自汇总后比较，差异额=实际−预算。预算>0时才计算差异率和完成率。
6. 零预算保留金额差异；缺失预算显示“缺少预算”。两者都不能显示正常完成率。
7. 收入、毛利、利润高于预算通常为有利，费用高于预算通常为不利；管理建议还需考虑业务背景。
8. 预算单价和实际分析单价都为折后、退款前单价。价格影响已含折扣，不重复增加折扣影响。
9. 预测保存版本和假设，截止月之前使用实际，未来月份使用预测；预算保持不变。
10. 情景测算按用户输入的价格、销量、成本和费用假设计算；销量对价格的反应不自动视为已知因果关系。

PVM、毛利差异桥和回测的详细公式以[指标与模型口径](financial_rules.md)为准。

## 8. 小样本与核对答案

以下案例彼此独立，金额单位为元。示例中的10月退款用于验证跨月规则，不表示已经获得10月完整实际数据。

统一销售明细：9月确认销售5件商品，原价120元/件，明细折扣50元，单位成本70元。折后成交收入550元，成交成本350元。

| 案例 | 事件 | 核算月份 | 净收入 | 净成本 | 毛利 | 核对重点 |
|---|---|---|---:|---:|---:|---|
| S01正常销售 | 无退款 | 9月 | 550 | 350 | 200 | 折扣只扣一次 |
| S02取消订单 | 原订单取消，未确认销售 | 9月 | 0 | 0 | 0 | 取消不计收入和成本 |
| S03同月退货 | 同月退回1件，退款110，成本转回70 | 9月 | 440 | 280 | 160 | 收入和成本均按事件调整 |
| S04跨月退货 | 9月销售，10月退回1件 | 9月 | 550 | 350 | 200 | 销售月保留成交 |
| S04跨月退货 | 退款110，成本转回70 | 10月 | -110 | -70 | -40 | 退款月反映负金额 |
| S05无退货补偿 | 9月补偿退款30，退货数量0 | 9月 | 520 | 350 | 170 | 只减收入，不转回成本 |
| S06多次部分退款 | 9月两次各退1件，每次退款110、转回70 | 9月 | 330 | 210 | 120 | 多条退款不能重复累加原销售 |
| S07全额退货 | 9月退回全部5件，退款550、转回350 | 9月 | 0 | 0 | 0 | 毛利率为空，不做0/0 |

S03毛利率=160÷440=36.36%。若公司当月只有S03这一笔交易且期间费用100元，公司经营利润=160−100=60元。费用不会再次从每个商品毛利扣除。

异常示例：同一明细累计退款600元、退货6件或成本转回400元，都超过原交易范围，应被识别。9月销售但退款日期早于确认日期的记录也应标为异常核实。

## 9. 数据与结论的边界

- 数据为模拟数据，生成规则和预设变化需保存。
- 数字分解可以指出差异贡献；业务原因需有活动、供货或定价信息支持。
- 共同费用未分摊时，不展示商品净利润。
- 第一版不据收入与毛利直接判断现金流、偿债或持续经营能力。
- 业务规则有变化时同步更新指标说明、样本、SQL和Python，记录变化原因。
