# 财务工作流程 · 0.5.0

日常仍从根目录的Windows `START.cmd` 或Mac `START.command` 打开。新版增加“预算工作台”和“对账与跟进”，原有七页保留。全部本机财务记录集中在一个文件中；无需增加企业数据库表，也没有新安装依赖。

## 1. 没有SQL预算时，先编制本机预算

1. 选择企业数据来源，进入“预算工作台→编制与导入”。选择预算年度、填写方式和分类粒度，然后下载模板。
2. 选择“金额预算”时，填写扣除退款后的净收入、扣除成本转回后的净成本。成本留空表示未知；已知零值必须填0。选择“驱动预算”时，填写成交件数、退款前均价、单位成本、退款和成本转回；只填金额的版本不会被强行拆成量价结构。
3. “销售预算分类”留空代表公司合计；也可选择商品、部门、销售员等已确认维度。费用分类另选，留空代表公司费用合计。费用部门不会自动关联销售部门。公司合计预算在真正按销售员过滤时不可比，不会被自动分摊。
4. 在Excel中保留“说明”前7行和各预算表第2行字段编号。月份填每月1日或YYYY-MM，分类填“分类参考”中的编码，可以复制行增加组合。只有月份、其余全部空白的行不导入；分类已经填写而金额缺失会报错。不要用显示名称代替编码。
5. 上传模板。企业、年度、字段、数字精度、非负金额、分类编码和同月同组合重复行会校验。新增业务计划编码需明确勾选允许，并保留警告；无缓存的公式和跨表/外部引用公式会被拒绝，建议在Excel中粘贴为数值。
6. 核对预览，填写名称、编制人和说明后“保存为预算草稿”。草稿不会改变分析结果。
7. 在“版本与发布”选择草稿，填写确认人和发布说明，勾选核对声明，再发布。顶部预算版本会自动切到新版本；经营总览、预算比较、预测和月报沿用同一版本。
8. 修改草稿：下载此版本明细，修改、上传并校验后，在原草稿下点“用上传内容更新草稿”。修改已发布版本：先“从此版本建立调整草稿”，再按相同流程替换草稿并发布。原始预算和每次调整均保留，年度和企业必须一致。

模板的金额单位固定为人民币不含税元，金额至分、驱动单价最多6位小数，件数为整数。空成本不按0处理。未填写月份不会自动补零，全年预算只有月份及实际/预测组合覆盖完整时才显示。计划可以从公司合计开始，不必为了使用程序编造销售员预算。

## 2. 核对数据，再确认月份

进入“对账与跟进→财务对账”。此处始终采用公司全口径，与顶部销售筛选分别标注。

程序在标准化和分类关联前，按读取字段独立计算每月销售、退款、成交成本、成本转回、费用及行数，再与标准明细和分析结果比较。这里检查的是程序读取至分析的勾稽，不能代替总账核对，也不能证明源系统数据完整。

从总账、业务核对表等独立来源录入五项参考金额，填核对人、期间和依据位置后保存。不要直接复制本页程序合计作为独立依据。未知留空；已知没有退款或费用时填写0。金额差异容许0.01元，来源和标准明细的内部金额、行数必须精确一致。

实际月份完整、必要来源已提供、历史成本可用、内部勾稽一致、五项独立参考核对通过后，进入“月份确认”，填写确认人和说明、勾选声明并保存。预算缺失不阻断实际月份确认，分类缺失单独展示涉及行数及收入；它不会让金额消失。

保存的是本程序的管理确认和当时明细，不会锁定SQL数据库，也不是审计意见。以后刷新旧月份发生变动时，显示新增/删除/修改及变化字段，可下载原快照与变更明细。需要更正时填写解除人和原因，再重新核对确认；历史修订不会删除。新增未来月份、发布预算或变更主题不使原月份误失效。

## 3. 无预算时，也能解释经营变化

在“月度趋势”下方查看“经营变化解释”。选择环比或同比，再选择净收入、毛利或公司经营利润。比较方式在当前使用中保留，月报使用最近选择的方式；重新启动默认环比。

历史实际是基期，不是预算。对共同商品依次分解总销量、商品结构、均价；基期未成交和本期未成交商品单列，不把“首次在这两个月出现”误称为新品。净收入另计退款变化，毛利另计单位成本和成本转回，公司利润再计费用。数学贡献提供核查方向，不是已经核实的业务因果。

退款按确认发生月计入，并继承原销售分类。可下载完整商品与分类比较、精确JSON。历史月份不完整、未确认统一件数、成本或退款来源不足时，相关桥显示不可用；已知收入可以继续展示。顶部有销售筛选时，不生成把公司费用分摊后的分类经营利润。

## 4. 将异常变成可跟进事项

在“对账与跟进→异常跟进”中设置阈值并填写扫描人，点击扫描。仅在点击时保存扫描事实，不会在浏览器后台执行任务。扫描使用当前销售筛选、已保存的分组和选择的环比/同比方式；公司费用超预算只在公司范围识别。

净收入历史下降、收入预算缺口、退款金额上升、公司费用超预算及分类收入下降，需同时达到金额和比例阈值；毛利率下降采用百分点及按本期收入计算的影响金额。基期为0或缺失时，不强算比例；界面列出未覆盖检查，0项异常不代表全部风险均已检查。退款指标含跨月退款，不能解释为某批销售的退货率。

选择事项，记录负责人、人工原因、待核实/已核实、核实依据、后续行动和截止日。“处理中”要求负责人、行动及截止日；标记原因已核实必须有原因和依据；解决或忽略必须写结果或理由。复盘月份与结论成对填写。

系统事实和人工判断分别保存。再次扫描更新事实，保留人工说明和状态；本次未再触发也不会自动解决。不同筛选范围的扫描不会把其他范围的事项改为未触发。可同时查看其他月份未结束事项，按原事项筛选查看当前月份收入、毛利作为复盘参考，结果仍由人员填写。事实来自另一数据快照时会提示重新扫描。

## 5. 月报、备份与迁移

“点评与月报”重新生成后，Excel仍为10张表，历史差异放在“驱动因素”，对账、确认与人工跟进放在“口径与追溯”；Markdown和精确JSON也携带对应记录。核对依据、跟进、历史比较方式、筛选、分组或预算发生变化，旧下载不再显示，需要重新生成。

本机数据路径如下，均不进入GitHub公开包：

| 文件 | 内容 |
|---|---|
| outputs/runtime/finance_workspace.sqlite3 | 预算、对账参考、月份确认、异常、阈值及追加操作记录 |
| outputs/runtime/dimension_views.json | 分类映射、布局及命名方案 |
| outputs/runtime/ui_preferences.json | 外观偏好 |

换电脑时，完整解压新版ZIP；先关闭两端程序，再单独复制需要的本机文件到新项目的相同位置。保留企业编号及接入配置的稳定profile_id或原配置身份，否则记录会按另一企业/接入分开显示。原始数据、MySQL可用连接及配置也须另行准备；不要复制旧电脑的.venv，不要公开上传财务工作区。

工作区采用SQLite事务和修订检查，过期页面保存时要求刷新，避免静默覆盖。程序不会把密码写入这里。它是单机管理工具：编制/确认人是人员填写的追溯记录，尚无登录鉴权、角色授权或企业审批流；不把该记录声称为不可篡改审计日志。目录不可写或文件异常时会提示，保留原文件，不自动清空重建。
