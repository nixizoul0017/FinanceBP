# 动态分类、联合汇总与方案

适用版本：0.5.1（兼容0.4.0接入与方案）。日常仍双击项目根目录Windows的START.cmd或Mac的START.command；无需另装数据库界面工具。Python及环境要求见[README](../../README.md)。

## 先体验一遍

1. 左侧数据来源选择“多维模拟数据”。这是独立样例，不替换原完整模拟数据。
2. 分类1保留商品、分类2保留渠道，将分类3改成销售员。下方可以选择林悦等人员；留空即全部，应用前原分析不变。
3. 打开“更多分类”，点击“添加分类”，把分类4设成地区。点击“应用筛选”；不选地区对象也会记住这个位置，下次默认展开。
4. 进入“维度分析”，分组字段依次选择销售部门、销售员。筛选决定分析哪些销售，分组决定结果怎样汇总；二者独立。选好后点击顶部“应用筛选”。
5. 选择B2026_TEAM预算，可按销售员比较；切到B2026_COMPANY，公司预算没有销售员粒度，实际照常展示，预算、差异和完成率不可比。
6. 进入“保存方案”，命名“销售团队”。先应用再保存；以后选择方案先填入待选区、清空待选对象，保留待选月份，应用后才生效。

同一分类只能占一个位置。更换位置的分类时，原来的待选对象自动清空；移除额外位置时也清除待选限制，均须应用后才改变分析范围。临时收起更多分类不会取消筛选，顶部保留当前范围和额外分类摘要。

## 应用与取消

顶部全部条件采用“先选择、再点击应用筛选”。“分析分组”只在维度分析页顶部出现，独立于销售范围；切换页面前先应用，否则待选内容会恢复为最后已应用状态。额外分类按是否配置维度决定默认展开，对象留空不影响这一规则。选项没有有效变化时应用按钮禁用，取消不运行计算。

候选对象按当前快照缓存，编辑不重新连接数据库。相同范围仅换单位或分类位置，复用金额、趋势、联合分组、历史桥及预测缓存。刷新若丢失分类或对象，已应用条件保留作核对依据，结果及下载暂停；必须核对待选条件后明确应用。原v1方案文件可直接继续使用，不保存待选内容。

## 新企业如何接入

沿用现有来源配置先声明销售、退款、费用和预算业务表。文件和MySQL均支持；本系统读取配置中的表，不扫描整个企业数据库。首次接入仍需确认人民币、不含税、元、件、销售确认日、退款确认日及完整历史范围。

读取成功后点左侧“分类识别与映射”。MySQL可先填写连接并点“识别分类（不加载）”，分类验证时重新输入本次密码，密码不保存。点击扫描后，系统读取字段类型、MySQL字段注释及最多1000条样例，显示候选数量、推荐名称、来源、样例和样本缺失率。样本缺失率用于预览，确认后目录显示完整销售行的缺失数。

推荐只是线索。部门、人员的数值编码也可识别；其他字段可手动添加。日期、金额、数量和流水号不默认推荐为分类。确认每个分类的显示名称、稳定编号、编码字段及可选名称字段，选择实际来源表、预算来源字段及适用版本。预算版本下拉来自扫描样例；未出现在样例中的版本可在配置文件的versions中设置。

需要独立员工资料时，先在“添加关联分类表”加入CSV路径或MySQL表名，再明确唯一关联键。仅支持多对一；重复键、无效映射或关联前后销售行数/金额变化会阻止保存。缺失关联保留销售金额，归入“未归属”。公司费用中的部门与销售部门分别处理，不自动合并或分摊。

历史部门应取交易时点的归属快照。若只提供员工当前部门，系统不能还原调岗历史；确认映射前需准备历史字段。退款继承原销售明细的分类，而不是退款当天的员工当前部门。

配置确认先完整验证数据，成功后才替换当前快照与本机映射；失败保留原映射。来源数据库只读，不会创建表或改写企业数据。

## 记忆与方案

本机文件outputs/runtime/dimension_views.json按“企业＋稳定接入配置”隔离，原子保存，含版本号。数据刷新、新增月份和显示名变化不会改变该身份；保持profile_id及维度id稳定即可继续恢复。不要给不同接入配置重复使用同一profile_id。网页为没有profile_id的旧文件配置按配置文件身份补充稳定标识，追加月份文件时仍可恢复布局；命令行旧版财务基准不变。来源配置主动修改分类、名称或核心映射时，以更新后的配置为准，不用旧的本机映射恢复已删除维度。

| 内容 | 自动长期保存 | 当前会话保留 |
|---|---|---|
| 分类位置、顺序、联合分组顺序 | 应用后保存 | 是 |
| 最近方案身份、已确认来源映射 | 是 | 是 |
| 具体商品、销售员等对象 | 否 | 九页间保留已应用值；未应用的修改在切页时放弃 |
| 月份、预测假设 | 否（分类方案不保存） | 按原页面行为保留 |
| 连接密码 | 否 | 仅本次读取/验证 |

手动调整在应用后保存为最近布局，命名方案保持原样，只有“更新当前方案”会替换它。方案管理可重命名、删除、导出、导入；名称不能重复。导入前检查维度稳定编号，任一失效维度会阻止整批导入；不静默换成其他分类。原布局中的失效维度显示提示并在待选区留空，暂停分析，核对后必须重新应用，改显示名称可继续按id恢复。

保存目录不可写时，当次分析仍可使用，并提示无法记忆；损坏文件不自动覆盖。多个浏览器会话共用同一项目目录的本机记忆，不是用户账号系统。具体对象不跨会话保存。

方案导出仅含方案名称、维度编号/显示名和布局，不含对象、密码和预测假设。换电脑可另带此JSON，先准备匹配的数据源配置与维度后再导入。接入映射不随方案JSON导出；可把审核过的v2来源配置随企业自己的私有资料迁移，不要上传真实企业配置或本机运行目录到公共仓库。

## 计算及导出边界

- 不同维度筛选取交集，同一维度多个对象取并集；全部对象不增加限制。槽位顺序不改变计算、预测训练粒度或金额。
- 分组毛利率以组内毛利÷组内收入重算。各组订单分别去重；同一订单跨商品时，组内订单数不能相加当公司订单数。
- 公司费用、经营利润始终明确显示公司全口径。销售员或部门销售毛利不减公司费用形成假分部利润。
- 预算按各版本已确认的维度比较。只摆出销售员位置、对象为全部，不影响公司预算；真正按销售员过滤或分组时才判断粒度。没有该维度的排名保留实际，预算和差异为空。
- 预测采用原来的三种方法，建模维度由v2配置forecast_dimensions固定，训练快照记录粒度。需要的历史有缺失归属或分类不在模型中时，细分预测显示不可用，保留所选范围，不借用公司预测。
- 维度分析图表最多前20组，完整表格及下载保留全部。数据下载包含新维度、缺失归属和联合分组；月报JSON记录筛选及分组，Excel的维度分析、销售/退款明细、预测和追溯说明同步记录。
- 应用筛选、月份、预算或分组变化，或修改报告假设后，旧月报提示重新生成；只编辑待选条件保留原月报，单位或槽位顺序不改变其内容身份；已下载Excel是当次快照，不随网页变化。

## v2配置结构

完整可运行示例在[多维文件配置](../../configs/multidimensional_files.json)，v1配置无需修改仍支持。v2在原配置上增加：

```json
{
  "profile_version": 2,
  "profile_id": "company-a-sales",
  "dimensions": [
    {
      "id": "salesperson_id",
      "label": "销售员",
      "bindings": {
        "sales": {
          "table": "sales",
          "field": "employee_id",
          "lookup": {
            "table": "employees",
            "key": "employee_id",
            "name_field": "employee_name"
          }
        },
        "sales_budget": {
          "table": "sales_budget",
          "field": "employee_id",
          "versions": ["B2026_TEAM"]
        }
      }
    }
  ],
  "lookup_tables": ["employees"],
  "forecast_dimensions": ["product_id", "channel_id", "region_id", "salesperson_id"]
}
```

这是补充字段片段，还需原配置中的entity_id、source、tables、coverage、semantics等。employees必须加入tables，且键唯一；files填写文件路径，mysql填写表名。binding.field使用原始字段名；核心规范映射继续使用原mapping。按销售行、订单、商品或客户关联，额外独立表需明确sales_key与source_key。预算versions省略表示全部已读取版本，不可给缺失该分类的预算误勾启用。

内置三维度编号保留，新增编号不得覆盖财务字段。缺失编码内部用“未归属（缺失值）”标识，界面显示“未归属”；来源不能使用该保留编码。数字1和1.0归一为编码1，字符串001仍保留前导零。

## 样例与开发验收入口

独立样例位于data/demo/multidimensional，252条销售、1条跨调岗退款、21条公司费用、192条销售预算、24条费用预算和6名员工。2026-08含一笔缺失人员和部门；员工1在2026-07调岗，8月退款仍归原6月D1部门。客户类型故意不进入预测模型，便于检查不可用提示。

生成器scripts/generate_multidimensional_demo.py只重建该独立样例，不改原演示文件。新增tests/test_dynamic_dimensions.py验证计算、接入、方案和导出；tests/test_dynamic_dimensions_app.py运行七个正式页面；tests/validate_dynamic_mysql.py只在独立33324端口临时实例验证，随scripts/validate_stage11_mysql.ps1运行，不使用本机3306企业数据。
